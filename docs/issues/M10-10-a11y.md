# Contexte

US-UX-05. Emojis comme icônes (`🦆📷✎▣✕🔴🟢▲▼‹›`) incohérents + lus par lecteurs,
textes `12-13px` (`resultCount`, `copyDate`, `badge`, `infoText`), cibles <44px
(pagination 36, options 35, recent 40, cancel 34), `+not-found.tsx` fautes
(`nexiste`, `daccueil`), lien `16px underline jaune` ~20px hauteur.

# Tâche

- Remplacer **tous** emojis UI par Feather (`camera, plus, x, chevron-*, check-circle,
  x-circle, search, upload, download, arrow-left`). Décoratif → `accessible={false}`.
- Textes : min `13px` (12→13 + lineHeight), `label 14px` min pour `resultCount/optionDescription`.
- Cibles : `minHeight:44 + hitSlop:8` partout (pagination, options, suggestions, cancel, lien 404).
- États : `accessibilityState {disabled, expanded, selected}`, `accessibilityHint` sur
  destructifs, `StatusBadge accessibilityRole="summary"` (RN 0.86 : pas de rôle `status`).
- `+not-found.tsx` : fautes corrigées, bouton primaire 48px `Retour à l'accueil` + icône.

# Critères de fin (DoD)

- [ ] 0 emoji UI restant (grep `🔴🟢🦆📷✎▣` dans `src/app|components` = 0 hors texte métier)
- [ ] Audit TalkBack/VoiceOver OK (navigation, tabBar, formulaires)
- [ ] Texte 200 % système sans casse (test accessibilité Android)

# Tests

- Snapshots a11y (rôles + labels), grep emojis en CI (optionnel).
- Manuel : lecteur d'écran, taille police max.
